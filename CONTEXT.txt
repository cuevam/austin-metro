PROJECT: Austin Metro Transit Data Warehouse
Portfolio project — Senior Data Engineering
============================================================

GOAL:
Build a real-time transit telemetry pipeline for Capital Metro (Austin, TX) buses,
from raw API ingestion through to a Grafana dashboard.

------------------------------------------------------------
STACK
------------------------------------------------------------
Warehouse:      ClickHouse (columnar DB, Docker on WSL2)
Orchestrator:   Dagster (asset-based pipeline, schedule every minute)
Visualization:  Grafana (ClickHouse datasource plugin, port 3002)
Language:       Python 3 (venv on WSL2)

Data Source:    Capital Metro GTFS-Realtime feed (vehicle positions)
                Texas Open Data Portal — JSON API, updates every ~15 seconds
                URL: https://data.texas.gov/download/cuc7-ywmd/text%2Fplain

Static GTFS:    CapMetro static schedule ZIP
                URL: https://data.texas.gov/download/r4v4-vz24/application%2Fzip

------------------------------------------------------------
PIPELINE ARCHITECTURE (Medallion / Lakehouse Pattern)
------------------------------------------------------------

BRONZE LAYER — bronze_transit_snapshot (Dagster asset)
  - Hits the CapMetro GTFS-RT API
  - Dumps raw JSON blob as-is into ClickHouse table: bronze_raw_json
  - Runs every minute via Dagster schedule (currently stopped, manual trigger)
  - Table engine: MergeTree, ordered by ingested_at (append-only landing zone)

SILVER LAYER — silver_telemetry (Dagster asset, depends on bronze)
  - Uses ClickHouse JSONExtract* functions to shred raw JSON into clean typed rows
  - Watermark pattern: only processes bronze rows newer than max(source_ingested_at)
  - Fields: vehicle_id, vehicle_label, trip_id, route_id, direction_id, start_time,
            start_date, schedule_relationship, latitude, longitude, bearing,
            speed_mps, speed_kph, current_stop_sequence, current_status,
            stop_id, vehicle_timestamp, source_ingested_at, processed_at
  - Table engine: ReplacingMergeTree, ordered by (vehicle_id, vehicle_timestamp)
  - Deduplicates repeated pings for the same vehicle

GOLD LAYER — gold_active_fleet (ClickHouse View)
  - Joins silver_telemetry with dimension tables
  - Uses argMax() to get the latest ping per vehicle within the last 15 minutes
  - Enriches with: route_short_name, route_long_name, route_color, trip_headsign
  - Source tables: silver_telemetry, dim_routes, dim_trips

DIMENSIONS — static_gtfs_dimensions (separate Dagster job, manual trigger)
  - Downloads CapMetro static GTFS ZIP
  - Parses CSV files inside ZIP: routes.txt, stops.txt, trips.txt, shapes.txt
  - Loads into ClickHouse: dim_routes, dim_stops, dim_trips, dim_shapes
  - Full truncate + reload on each run (static data, infrequent changes)

------------------------------------------------------------
CLICKHOUSE TABLES
------------------------------------------------------------
bronze_raw_json     raw_payload String, ingested_at DateTime
silver_telemetry    typed telemetry columns (see above)
dim_routes          route_id, route_short_name, route_long_name, route_color
dim_stops           stop_id, stop_name, stop_lat, stop_lon
dim_trips           trip_id, route_id, direction_id, trip_headsign
dim_shapes          shape_id, shape_pt_lat, shape_pt_lon, shape_pt_sequence
gold_active_fleet   VIEW — latest ping per vehicle enriched with route/trip info

------------------------------------------------------------
DAGSTER DEFINITIONS (definitions.py)
------------------------------------------------------------
Assets:     bronze_transit_snapshot, silver_telemetry, static_gtfs_dimensions
Jobs:       transit_sync_job (bronze + silver), dimension_sync_job (dimensions)
Schedules:  transit_schedule — cron "* * * * *", default status STOPPED
